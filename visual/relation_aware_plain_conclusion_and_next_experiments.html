一句话结论

当前结论是可用的，但要讲得克制： Relation-aware repair 能稳定提升显式空间关系的满足率；direct repair 提升最大但移动更激进，也可能带来轻微 mesh collision 增加；floor-prior 更保守，移动更小；如果要说“几何副作用受控”，应该使用 collision-gated floor-prior 版本。
算法能跑通

环境、checkpoint、数据和 raw mesh 都已经配好。三类房间完整 split 都跑过，没有再卡在缺特征或缺 mesh。

bedroom、livingroom、diningroom 的 repair 后关系满足率都明显高于原始 InstructScene 输出。

论文还不够硬

目前公平 baseline 是原始 InstructScene。若想更有说服力，需要补强 baseline 对比和参数消融。

通俗解释：这些数字说明了什么

原始 InstructScene 可以生成看起来合理的房间，但它不一定严格实现文本里的空间关系。例如文本要求“椅子靠近桌子”或“床在柜子左边”，模型可能选对了物体，却在最终 layout 里把位置放错。

Relation-aware repair 做的事情不是重新训练大模型，而是在生成后检查这些明确关系有没有被满足。如果没满足，就在地面平面上小幅移动相关物体，尽量把关系修回来。

现在的实验说明：这个后处理层确实有效。更激进的 direct 版本修得更多，但物体移动更大；floor-prior 版本修得保守一些，关系提升少一点，但平均移动大幅降低，更像论文主方法应该采用的版本。

现在能写进论文的说法

推荐写法： 在 InstructScene 官方验证 split 和 checkpoint 下，我们的方法作为一个无需训练的 verifier-repair 层，稳定提升显式空间关系满足率。直接修复版本提升最大；floor-prior 版本显著降低物体移动；collision-gated 版本在保持正向关系提升的同时，将 mesh collision pair rate 控制在 baseline 水平或更低。
不建议写法： 不要说已经超过 ReSpace 或 SDGScenes；不要说这是第一个 relation-aware 3D scene generation 方法；不要说所有视觉质量都变好；不要说未 gated floor-prior 一定减少 mesh collision。

是否需要强 baseline 对比？需要

如果只是为了证明代码能跑、方法内部有效，目前结果已经够。但如果目标是写论文或投稿，仅和原始 InstructScene 比会显得证据偏窄。强 baseline 不一定要马上完整复现成功，但至少要清楚区分“公平可比 baseline”和“相关但协议不同的方法”。

baseline 现在状态 建议怎么处理

是否需要参数消融？也需要

参数消融的作用不是让结果更花，而是回答审稿人很可能问的问题：为什么选这个版本？为什么移动阈值是 1.8？为什么 repair passes 是 2？为什么 close/far 阈值是 0.75/1.6？如果这些没有交代，方法看起来会像“调出来的”。

优先级 1：max repair move

建议跑 0.8 / 1.2 / 1.8。这是最重要的消融，因为它直接解释关系提升和移动幅度之间的取舍。

  • 指标：relation gain、avg movement、mesh pair delta。
  • 预期：阈值越大，关系提升越高，但移动和碰撞风险也更高。

优先级 2：repair passes

建议跑 1 / 2 / 3。它回答多轮修复是否真的必要。

  • 指标：relation gain、repair skipped、avg movement。
  • 预期：2 轮可能是比较好的折中，3 轮收益变小。

优先级 3：overlap weight

建议跑 0 / 0.5 / 1 / 2。它解释 floor-prior 为什么不是单纯移动物体，而是在考虑重叠风险。

  • 指标：relation gain、footprint overlap、mesh pair rate。
  • 预期：较高 weight 会更保守，但可能牺牲关系提升。

优先级 4：close / far threshold

建议小范围跑，例如 close 0.6 / 0.75 / 0.9，far 1.4 / 1.6 / 1.8。

  • 指标：关系满足率和 per-relation breakdown。
  • 预期：这个消融可以说明指标不是被某个任意距离阈值“卡”出来的。

最终建议

目前最稳的论文结构是：主表用原始 InstructScene vs direct vs floor-prior vs collision-gated floor-prior；补充表放 multi-seed、参数消融、per-relation breakdown；相关工作里认真讨论 ReSpace、SDGScenes 和 CommonScenes，但在没有共享协议复现前不要写超越它们。
