EG07 必须提供的数据

EG07 的核心任务不是再换方法，而是导出一个能被 EG05/EG06/EG08 直接读取的全量标准数据包。 如果 EG07 数据不规范，后面的公平 baseline 和统计分析都会卡住。

1. 全量布局 JSON

字段/要求 必须提供 说明
格式 {"layouts": [...]} 必须能直接作为 evaluation/independent_relation_evaluator.py 和 scripts/run_eg06_movement_baselines.py 的输入。
场景数量 531 scenes bedroom 162、livingroom 192、diningroom 177。
每个场景至少两个 variant baseline + collision_gated_floor_prior EG06 要用二者计算主方法实际移动预算。
每个 layout 的基础字段 scene_id, room_type, layout_variant, source_config_id, objects, target_relations 字段名要和 EG05 fixture 保持一致。
objects 字段 index, category, center, size, yaw center 必须是 [x, y, z]，同一场景不同 variant 的 index 必须稳定。
target_relations 字段 relation_id, subject_class, predicate, object_class 最好只放 baseline layout 上，其他 variant 可为空；EG05 会用 baseline 冻结 instance pair。

2. 运行记录和可追溯信息

需要记录 原因
code_commit说明这批数据从哪个代码版本生成。
config_path 和 config_sha256证明没有偷偷改阈值。
command 和 log_path让其他人能复现和排查失败。

seed_or_seed_policy记录随机策略；如果最终跑 seeds 0/1/2，也要分开记录。
